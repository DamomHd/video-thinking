# 改成你自己的风格

> 借鉴 lemo-opuscar 的 `MY-STYLES.md`（原文在 `docs/method/opuscar/my-styles.md`）。本工程的做法以本文为准。

用户想要「把某个风格改成自己的版本」「从空白做一个库里没有的风格」时走这个流程（「我想改风格」「做成我自己的风格」「从空白开始」）。用户认可某部**已经做完的片子**的样子、想沉淀成风格时，用的是另一条更短的路：`vw style save <片> --id=…`。

和用户用中文交流；风格文件用中文写，名字中英文都可以。

## 0. 文件放在哪

- 用户点头之前是**草稿**：`out/style-drafts/<id>/`（`vw style fork` 起草），风格库和注册表都不动。
- 用户点头后 `vw style keep <id>`：草稿挪进 `src/styles/<id>/`、登记进 `src/styles/index.ts`，以后说「用 <名字> 风格做……」就能用。
- 草稿里的文件：

| 文件 | 内容 |
|---|---|
| `STYLE.md` | 完整的风格说明，读起来和收录风格的 STYLE.md 一样（改库里风格：底子全文 + 改动写进对应的节；从空白：十一节都写满） |
| `CHANGES.md` | 每个决定一行：节、原来、现在、为什么、分组。**用户批的就是这张表**，样片也照它查 |
| `style.ts` | 参考色板与字体（风格库现有字段，色板只是参考） |
| `README.md` | 一句话、用来做什么（片型、受众、平台、画幅）、文件说明 |
| `refs/styleframe.png` | 用户认可的风格帧；改库里风格时还有 `refs/styleframe-vs-base.png`（同一帧，左底子、右新风格） |
| 样片 | `src/films/<id>-test/`（15–30 秒）；有基准作品时，进库后把它软链成 `refs/demo.mp4`（总览页直接播） |

名字和 id 不能和风格库里已有的重复（`vw style fork` / `keep` 会查）。

## 1. 从哪儿开始

- **改库里的风格**：用户点名一个（`vw style list`）。没点名时，按用途推荐两三个放在最前，附海报帧，让用户自己打字说选哪个。**只有一个底子**；想混两个，就取本质最接近的那个当底子，另一个只拿用户要的部分，写进 `CHANGES.md`（「借自 <id>」）。
- **从空白开始**：用户用自己的话描述，或者给一张图、一支片。挑一个库里的风格当**技法底子**（材质和画法最接近的，代码在它上面搭），最多再借两个风格的手法。第一个问题就问这个：我的选择和理由各一行，次接近的作为其它选项。

两种情况，第一个问题之前都先把底子的 `STYLE.md` 读完；这条流程里可以先读底子的 `DEMO.md`、`vw style demo <id>` 取样片源码（风格帧要用它的技法）。样片的故事要和底子样片不一样。

## 2. 一起定方案

一直问到 `STYLE.md` 每一节都定了、用户知道每个选择的代价。

**怎么问**
- **一次一个问题**，用 AskUserQuestion：2–3 个选项，推荐的放第一个并标（推荐），每个一句话说它会让片子变成什么样；最后一个选项是「自由对话」。
- **自由对话**：用户选了它就不再一题一题问，在对话里贴一张清单：已经定的、还没定的（每项附我的推荐，改库里风格时标上分组）。用户用自己的话回答，顺序随意。拿不准的项给两三个具体方向。每轮更新清单；全定了或用户说「你定」，就进汇总。
- 每个问题都带推荐和理由，理由来自底子的 STYLE.md 和用户说过的话，举这个风格自己的例子，不说空话。
- 能查到的不问（底子 STYLE.md、风格库、用户的文件）。
- **最多十来个问题**（技法底子算一个）。相关的放一起问（动效和声音、镜头和原生手法）。用户说「你定」「都按推荐」，剩下的按推荐填好，一条消息列出来，继续。

**顺序**（用户已经说过的跳过）：
1. **用途**：做什么片、给谁看、发在哪，由此定画幅（竖屏 1080×1920 或 1080×1440）；有没有品牌色、logo、字体、固定角色（文件之后由用户给）。
2. **改哪里**：
   - *改库里的风格*：先用这个风格自己的节和例子讲清三组，再问想动哪些（可多选）：

     | 分组 | STYLE.md 的节 | 跟用户怎么说 |
     |---|---|---|
     | **放心改** | 配色（在它的配色逻辑之内）、字体、动效（快慢、动多少）、声音（乐器、疏密）、原生手法（加一个或换一个） | 风格还是它自己；每项给两三个主意 |
     | **一改就变味** | 材质与渲染、配色逻辑本身、镜头语法 | 可以改，说清每项改了会丢掉什么 |
     | **不能改** | 本质（和「它不是什么」）、引擎 | 那就是另一个风格了，不是它的版本；直说，并推荐更近的底子 |

     放心改的项收窄了本质里的某句话（三种墨变两种），就顺手改那句；本质不变。
   - *从空白开始*：先定本质：一句它是什么、一句它不是什么。再定材质。
3. **逐节定**：只定涉及的节，按 STYLE.md 的顺序：材质与渲染、配色、字体、动效、镜头、声音、原生手法。每项两三个具体方向。
4. **名字**：中文、英文或都要，和 id。

**帮用户改得好**（多数人知道想要的感觉，不知道该动哪一节）：
- **从用途出发**：每周的品牌快讯要字好读、开头固定；给小朋友的要形状大、读得慢。
- **把模糊的愿望翻成选项**，不悄悄改：

  | 用户说 | 通常意味着 |
  |---|---|
  | 高级一点 | 颜色更少、明暗反差更大、动作更慢、留白更多、字更轻 |
  | 活泼一点、年轻一点 | 强调色更亮、卡拍剪切、更弹的缓动、更多打击乐 |
  | 安静一点 | 速度更慢、停留更久、动的东西更少、乐器更稀 |
  | 像我们品牌 | 品牌色当强调色而不是底色；标题用品牌字体；开头和结尾放 logo |

- **品牌**：保留底子的明暗结构，字才好读；品牌色先作为强调色进来。品牌字体要覆盖片子的语言（中文片要有中文字形）、并允许用在视频里。logo 和字体由用户提供。
- **参考图 / 参考片**：说出它成立靠的两三点，各对应到一节，并说哪几点会动到本质。
- **保住标志**：原生手法是风格被认出来的地方，最多换一个。
- **成套的改动**：动作快了声音要更密；底色暗了要查字的对比；换了材质要把它的坑写进「媒介的坑」。
- **改库里风格一轮最多五处**；多了用户也判断不了。语言逼出来的改动（底子没有中文字体，换一个）不算。
- **全部用代码画**：不用生图、生视频。不是代码画的东西（图片、字体、笔触或地图数据、采样）要么是用户自己的，要么是开放授权（CC0 / CC BY / OFL），记进交付的 CREDITS。
- **不需要风格的东西**：故事、结构、开头结尾、角色、场景、节奏、口播（每个风格的「变化空间」）每部片都可以自由变。用户只想要这些，就不需要自己的风格，做片时说就行。

方案定了，用中文给用户一份短汇总：每个决定改前、改后、代价。**等用户点头**，再写下来。

## 3. 写下来

`vw style fork <底子> --id=<id> --label=<名字>`（从空白：`vw style fork --blank --technique=<底子> --id=…`）起草稿，然后：
- `STYLE.md`：改库里风格的，把改动写进对应的节，读起来要完整（不留「见底子」）；保留仍然适用的坑，加上改动带来的新坑。从空白的，十一节都写满，引擎一节先写技法底子。
- `CHANGES.md`：每个决定一行。
- `style.ts`：按新配色调参考色板和字体。

## 4. 先看一张风格帧

用真实的画面代码渲一张（从底子的技法出发，代码拷进样片目录，不改风格库）：先搭 `src/films/<id>-test/` 的骨架，`vw still <id>-test --at=…` 出一帧。对照新的 STYLE.md 查一遍，改一轮。
- *改库里风格*：同一帧用底子的设置（它的颜色、材质、字体）再渲一张，`vw style vs <底子帧> <新帧> --out=out/style-drafts/<id>/refs/styleframe-vs-base.png`：左底子、右新风格，只有改动处不同。
- *从空白*：没有可比的，单独给用户看；有参考图就放在旁边。

存成 `refs/styleframe.png`。**给用户看，等回复**。要改就更新 STYLE.md 和 CHANGES.md 再渲。两轮还不对，直说，并推荐更近的底子。

## 5. 样片（15–30 秒）

一支短片，任务是证明这个风格成立，不是正式制作：
- **题目**：用户给就用；不给就选一个简单、有动作、有一点光的（风大的海边放风筝、清晨第一班电车）。不用底子样片的故事。
- **`CHANGES.md` 每一行都要在画面里清楚出现至少一次**，原生手法出现一次。
- 配乐和音效；没有口播、没有字幕，除非用户要（口播要先问）。
- 一个结构就够（不出三个方向）、不出分镜。这么短的片，一次真静默、三种运镜就够。
- 照常过 `vw check`、出片、`vw review`，修一轮。

## 6. 留下来

告诉用户样片在哪、每处改动在第几秒能看到，然后问（AskUserQuestion）：
1. **留下作为我的风格**（推荐）：`vw style keep <id>`，告诉用户以后怎么用（「用 <名字> 风格做一支……」）。
2. **再改一轮**：只改用户说的，再问一次。
3. **先不留**：草稿留在 `out/style-drafts/<id>/`，告诉用户路径；以后说「把 <id> 留下作为我的风格」就 keep。

## 7. 改它、用它

- **还不对**：改 STYLE.md 和 CHANGES.md，重渲风格帧和样片。只改用户说的。
- **用它做片**：读它的 STYLE.md，照常走导演流程（SKILL.md），默认画幅按它的 README。手法先看它自己的样片（`src/films/<id>-test/`），再看底子的。样片只是一个例子，不照搬它的故事、镜头和时间轴。
- **底子更新了**（重跑收录导入后底子的 STYLE.md 变了）：提一次，问要不要把有用的修正带进来；没问过不改。
