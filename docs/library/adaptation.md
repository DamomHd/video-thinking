# 改写说明：从 huashu-motion 借了什么、改了什么

> 2026-10-26。借鉴 huashu-motion v0.1.1 的方法与语言库（`languages/` `techniques.md` `formats.md` `product-fit.md`、`docs/method/` 下的 `director.md` `visual-direction.md` `rhythm.md` `colour.md` `craft.md`，原文照收、开头注明出处）。下面是本工程不照搬、或另加的部分。原文与本文冲突时，**以本文为准**。

## 1. 引擎不同
原文是单个 HTML + GSAP；本工程是 Remotion + three.js + Blender + 自建配音平台。命令与原语的换算见 `engine-map.md`。原文里「一个 HTML 一部片」「变量面板」「studio 指着改」对应本工程的「一个世界组件 + 镜头清单 + 动作事件表」和 `vw studio`。

## 2. 新增片型：汇报片（方案讲解 / 项目汇报 / 复盘）
本工程最常做的片型，原文的 formats 里没有。

| 项 | 默认 |
|---|---|
| 时长 | 45–90 s |
| 观众 | 评审、负责人；**清晰优先于炫**：关掉声音也要看得懂主线 |
| 结构 | 一句话主线 → 4–7 段，每段一个结论（标题就是结论句）→ 结尾回到主线那句话 |
| 路线 | 默认 continuous（一个世界、镜头带人走），在论证的转折处可以有一次短的 montage 爆发 |
| 节奏 | 90–130 BPM；每段一次落点，全片一个主镜头放在最需要「说服」的那一段 |
| 语言 | 按每段的讲法分别选（见 `README.md`「怎么选」最后一段），一根脊梁串起来 |
| 结尾 | 回到那句主线 + 关键数字一排，不是品牌 logo |

## 3. 不照搬「发布片默认要有能量」
原文 `director.md §3` 说发布片无论品牌都默认 100–125 BPM、30–60% 处一段快切爆发。这条来自对发布片的统计，**不自动用于汇报片**：汇报片的节奏由内容的论证结构决定（蓄力在论点前、释放在结论上），不为了「酷」而快切。发布片仍按原文。

## 4. 出方向的时机
原文默认每部片都出三个方向。本工程：**开工前先跟用户问答**（一条消息，写好缺省值，用户逐行改）；**用户没给足够参考时**才出三个方向，每个方向一张真实分辨率的关键帧（`vw still`），由用户挑或混。用户给了明确参考或风格时，直接按它做，交付时用一句话附上「放大 / 意外」两个备选。

## 5. 风格库：默认不选，事后沉淀
原文的「质感与声音」层默认由每部片自己设计（配色按 `docs/method/colour.md` 从内容里找）。风格库（`src/styles/<id>/`，只有色板、字体、图框、气质描述、参考帧）不是起点，而是沉淀：用户认可某部片的样子后用 `vw style save` 收进去，做系列片时沿用。风格库里不放动效参数、组件默认值、镜头偏好——这些由模型按内容设计。

## 6. 质量关卡
原文的「四张海报帧」和「独立审片者」：
- 海报帧照收，作为自查：四张海报帧按 `docs/method/taste.md` 的评审表评一轮（六维各 10 分，低分项建议先改）再铺全片；交付前再评一次。评审是自查工具，不限制设计。
- 独立审片者（另起一个没参与制作的代理冷看）：**TODO**，用户决定后续再考虑。现阶段由模型自评，自评要写出具体缺陷。

## 7. 暂不支持
- 口播 / 字幕对齐（原文 `OM.cue` / `om voice`）。
- 真人出镜、照片主导、角色类语言需要外部素材；没有素材时不选。

## 8. 画法片段（实现）
huashu-motion 的 8 个模板里收了 7 个画法的实现（`src/vendor/huashu-clip/`，原样收录；`src/components/clip/` 按 Remotion 重写了运行层），见 `clip.md`。不收 storytime（作者本人卡通形象不在授权范围内）。它们在本工程里是**积木**：一段内容适合时用，不把整部片做成某个模板。

## 10. 笔刷手绘动画（ClaudeAnimationBase）
引擎（p5.js + p5.brush 的平涂、水彩、排线、墨线，线条按 12 次 / 秒「boil」；角色骨架：5 个手绘转身角度、31 种情绪、自动带预备和反应的表情切换、跳 / 惊吓 / 走路 / 弹簧等表演函数）原样收在 `public/vendor/claude-animation-base/`，指南原文在 `docs/method/animation-guide.md`。
- **用法**：`components/paint/PaintCanvas`（`draw` 绘制函数里用 `cab()` 拿引擎；也能跑上游写法的 `scenes` 脚本和 `loop` 设定图）。帧是时间的纯函数，可乱序、可并发；同一渲染页只有一份引擎。
- **指南里的「三个目标」「七条规则」只在选了这种画面语言时适用**（手绘卡通、角色表演）。其中「不要文字」「不要 3D」是这种语言自己的纪律，不是全局规则：汇报片照常有字，3D 照常用 three / Blender。可以在一部片里只有一段用笔刷画面。
- **通用、建议任何片子都用的**：①「read」计时法（rule 4）——给每个镜头列出观众必须看懂的每件事、各自的起止时间，一次只让观众读一件事，动作可以快、意义要留够时间，决策单「节奏」一节按这个写；② 动画原则（预备、挤压拉伸、慢进慢出、弧线、错开、夸张、关键姿势）；③ 自查纪律：缩略图看全片、连拍看动作（`vw still --strip`）、局部放大看细节（`--crop`）。
- **角色**：指南默认角色是 Clawd，可以直接用，也可以照骨架（`EMO` 情绪表、`VIEWS` 转身角度、`draw` / `armL` / `armR` 挂件）改成别的角色。
- **成本**：本机（Intel 核显）简单场景约 1 秒 / 帧，上游示例约 0.9 秒 / 帧；水彩填充（`fill`）多了会更慢，按上游建议多用平涂（`wash`）和墨线。
- **字**：上游手写体只有拉丁字母；中文要写字时给 `letter()` 传 `{ font: '…px 字体名' }`。

## 11. 收录的风格（lemo-opuscar）
lemo-opuscar（LemoLab，MIT）的 59 个风格整份收进风格库（`src/styles/<id>/`，2026-10-26 用户决定；登记在 `src/styles/opuscar.ts`，`scripts/style/import-opuscar.ts` 生成，可对上游重跑）。
- **用法**：片子默认不选风格；开工前问答时，内容和某个风格对得上，可以把它列为选项（附海报帧 `refs/poster.jpg`）。选了就读它的 `STYLE.md` 原文照着做，`DEMO.md` 只是上游那一支样片的例子，不照搬故事和镜头。
- **引擎换算**：原文写给上游的「每帧一个 HTML 页面 + `window.render(t)`」引擎。本工程里画面用 Remotion 组件写（`t` 作 prop、纯函数），Canvas 类风格可直接在组件里画 2D Canvas，WebGL 类走 `three/FilmCanvas`，笔刷类可用 `paint/PaintCanvas`；声音按原文的声音调色板走本工程的配声平台（`events` → `autoSpots`、`vw music`）。原文里 `still.mjs` / `readcheck.mjs` / `mux.sh` 等命令对应本工程的 `vw still` / `vw check` / `vw render`。
- **样片源码**：`vw style demo <id>` 取到 `out/styles/<id>/demo/`，读来学具体手法（它怎么画墨、怎么做光、怎么混音），不在本工程里渲。
- **色板只是参考，不固化主题色**（2026-10-26 用户定）：`style.ts` 的色板取自样片源码 + 原文写明的色值，不足 3 个时补海报帧主色（`poster1…`，可能漏掉面积小的强调色）。片子选了收录风格时，**配色由模型按片子的需要、照 STYLE.md「Colour logic」的逻辑在自己的 theme.ts 里定**（守的是配色逻辑，比如「只有一个强调色」「问题色只在问题存在时出现」，不是具体色值）。字体取自原文「Type」一节点名的字体，字体文件在样片源码里。
- **重名**：上游 `blueprint` 和本工程自有的「图纸」重名，收录为 `blueprint-opuscar`。
- **授权**：提示词与代码 MIT；海报帧和关键帧（`refs/`）CC BY 4.0，署名 LemoLab 并附仓库链接。

## 12. lemo-opuscar 的工具链与导演经验
声音和检查工具原样收在 `vendor/lemo-opuscar/`（Python，`.venv`；见那里的 NOTICE.md），导演 / 技术指南原文在 `docs/method/opuscar/`。本工程的接法：
- **采样配乐**：不用上游「每部片手写 Python 谱」的做法，而是让本工程的结构化作曲（`structure.ts`：段长、律动、起势、高潮小节）照旧写谱，`scripts/composer/sampled.ts` 按配器方案换成真实乐器演奏。改了两处：力度朝高潮走；**高潮前一小节收一口气**（本工程的分析器按能量跳变找高潮，起势比高潮跳得猛会把高潮测错一小节——实测过）。
- **配音**：`vw voice` 包了上游三个脚本；配音放进片子混音需要新的音频层，未做（等确认）。
- **读字检查**：上游要片子自己登记 `window.TEXTS(t)`；本工程直接读 DOM（`components/ReadProbe.tsx`，只在 `vw readcheck` 时挂上），文字按块归并，翻牌格之类一两个字的小块并到所在的一行，位置不变只换字的算同一段，被原地换掉的中间态不报。
- **响度**：目标同上游（−14 LUFS、真峰 −1.2），做法不同：上游 `mux.sh` 用 loudnorm 两遍，线性增益超真峰时会退回动态模式压缩；本工程改成限幅只削瞬态 + 纯增益，保住「静默 → 重击」的反差。
- **从导演指南收进本工程的几条**（决策单模板已加）：高潮前至少两次真静默，静默后的第一个声音要是全片最重要的声音之一；至少两次用声音带转场；至少四种不同的运镜、一个让人记住的标志镜头；混音后量频带，20–120 Hz 比中频低约 3 dB；人声先压缩再按 RMS 比配乐高约 10 dB；字幕至少停 1.8 s。
- **第二批（2026-10-27）**：画面字幕组件（`components/Subtitles`，缺省中性、样式外露）、字幕压字检查（读字检查里）、成片混音后的口播再核对（`vw voice final`，出片时自动）、频段平衡进出片验收、交付用 CREDITS（`vw credits`，出片时自动）、字体落地（`vw font fetch`，中日韩按片子取子集，`useLocalFonts`）。中文口播的约定照上游：字幕写数字、念的写读法（`text` / `say`）。
- **不照搬的**：上游「每部片一个 HTML 页面、`window.render(t)`」的引擎约定（本工程是 Remotion 组件）；它的读字检查要片子登记文字（本工程直接读 DOM）。

## 13. OPUSCAR 98 的片段风格（参考）与「改成你自己的风格」
- **OPUSCAR 98**：上游纪念片里 98 部最佳影片各一段约 5 秒画面的风格（`styleboard/opuscar98_styles.json`）。**不进风格库**（2026-10-27 用户定：只有完整的风格才收录），放在 `docs/library/opuscar98/` 作参考：每个一份 md（中英文提示词原文、说明、示范分镜）+ 画面帧（CC BY 4.0）。用法：某一段画面想要这种质感时借它的提示词写进决策单，声音、镜头、坑由模型自己补。电影名只是风格来源，片子里不出现原片的名字、角色、画面或音乐。
- **改成你自己的风格**：流程见 `docs/method/style-workshop.md`（借鉴 `MY-STYLES.md`）。和上游的区别：草稿放 `out/style-drafts/`，确认后进本仓库的 `src/styles/`（上游放用户主目录的 `~/lemo-my-styles/`）；不用 style.json，底子写在 STYLE.md 标题下和 README 里；样片是本仓库的一部片 `src/films/<id>-test/`。

## 14. 从 lemo-opuscar 的用法里借的（2026-10-27）
对照上游 `AGENTS.md`（Style and story / Finding the style / Workflow）和 `DIRECTOR.md` §1–5、§11，收进做片纪律（SKILL.md）和决策单模板：
- **标杆**：动笔前模型自己挑一两部标杆作品，写学什么、不拿什么（不用样片当标杆）。决策单新增必填一节「标杆」。
- **先写方案再看样片**：沿用库里的风格时，决策单写完之前不读 `DEMO.md`、不取样片源码；样片只学技法。交付前「和样片对照」六项至少四项不同（`vw review` 查，拼 `vs-demo.png`）。
- **方案更细**：三个候选结构 + 选择；镜头表写为什么这样拍；逐秒节拍表；拍点图；每段声音设计表；字幕与标题设计。
- **先看样子**：有角色时加角色设定图。
- **分镜可选**：问答里问，缺省不要；要了就 `vw storyboard`，等点头。
- **挑风格**：缺省仍是自定主题；想从库里挑时推荐两三个 + 贴分类全表（`src/styles/README.md`），自有风格在前。
- **问答多两项**：语言、用户自己的素材。
- **交付多一张海报图**（`poster.jpg`）。
- 没借：插件启动时问语言 / 入口菜单；每部片单独项目目录 + 一条命令的 build.sh（本工程是一个仓库多部片，用 `vw render`）。

## 9. 参考的角色
参考片是好例子之一，用来学「为什么好」（`exemplars/`），不是要对齐的目标。不做「和参考并排比像不像」这种验收。
