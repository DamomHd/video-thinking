# 暖纸产品叙事 · Warm-paper Product Story

从空白开始；技法借自 活体实机录屏 · Living Screencast（living-screencast），另借 暗色科技发布（dark-keynote）、档案灯台（archive-lighttable）、数据实物化（data-physical）、数据叙事（dataviz）的手法。
基准作品：`loomcare.mp4`（LoomCare 产品片，4 分 47 秒，参考帧在 `refs/`，量出来的数据见 README）。

> 一部讲「我们做了什么、它怎么工作、结果如何」的产品 / 项目片：暖白纸面上，真实感的产品界面和真实感的单据是主角，按一个人的一件事展开；章节之间插进暗场里的电影感一镜，让「系统内部」被看见；结尾用一排大数字把工程量摆出来。
> 用途：企业内向上汇报、项目演示（结合具体项目做 mock 演示）、产品发布前的内部讲解。

## 1. 本质，以及它不是什么

- **一个人的一件事开头**：第一镜是一个具体的人和一个具体的物件（「出院那天，她带回家 8 页纸」），不是 logo、不是口号。整部片是这件事被系统一步步接住的过程。
- **主角是可以用的产品**：界面是用代码重画的真实感 UI（对话、卡片、列表、手机屏、后台表格），数据是这个项目的 mock 数据但写得像真的（单号、时间、金额、状态全有）。观众看到的是「它在工作」，不是「它很好看」。
- **真实感的单据**：发票、清单、病历、合同这类纸面物件按真实比例画，敏感处用黑条遮挡，盖章、二维码、表格线都在；它们是证据。
- **两种光**：大部分时间是均匀的白天光（暖白纸面，很浅的阴影）；章节之间插进**暗场电影感一镜**（深暖黑底，金色的光、聚光灯、发光的点阵或时间线），让抽象的「系统内部 / 能力 / 规模」有一个具体的形象。暗场只占全片 10–20%，每次 3–8 秒。
- **每段一句结论**：小号编号 + 一句粗黑标题（带句号）+ 一行灰色副句，标题就是这一段的结论。
- **没有口播**：靠字、画面和声音讲完（要口播先问用户）。

不是暗色科技发布（不是一直黑底；它的暗场只是插叙）；不是工程图纸（blueprint：没有图框、点阵网格，允许圆角卡片和浅阴影）；不是录屏（界面全部重画，镜头可以钻进任何一个元素）；不是 PPT（没有页眉页脚条、没有项目符号堆砌；每一屏一个主体）；不是品牌广告片（不靠情绪画面，靠可验证的过程和数字）。

## 2. 材质与渲染

- **底**：近白暖纸 `paper`（#FCFAF9），不加网格、不加图框；可以有极淡的纸纹和很柔的暗角。留白大，内容占画面 55–70%。
- **界面**：卡片白底 `surface`（#FFFFFF），1px 浅描边 `line`（#EFEAE5），圆角 10–14px，阴影极浅（y 6–16px、模糊 24–40px、不透明度 4–8%）。界面里的字用系统中文黑体，层级靠字重和灰度，不靠颜色。状态胶囊（「已识别」「已放行」）用很淡的底色 + 深色字。
- **手机与电脑**：手机用写实但干净的机身（PhoneShot / Phone3D），屏幕里是同一套界面；电脑可以只画线稿（细灰线的笔记本轮廓）。设备只在「同一份数据，两个出口」这类时刻出现。
- **单据**：`docPaper`（#E8DDD1）偏暖、略带纤维；表格线、印章、二维码、手写体按真实比例；敏感信息用黑条；可以挂在一根细线上、摊在桌上或斜放带景深。开场可以用**微距**：镜头贴着纸，浅景深，只有一行字清楚，一支荧光笔划过关键词。
- **暗场插叙**：深暖黑 `stage`（#14110C）；主体是发光的线框或实物——等距的芯片 / 能力板（金线 + 中心光点）、聚光灯下吊着的标签纸、透过点阵的光、发光的时间线和光点。金色 `gold`（#E7C877）是光，不是颜色块；有真实的景深、辉光和微尘。
- **数据**：大数字（细或常规字重，不加粗）+ 小标签；条形用白色实物（像白模或亚克力块，3D、有阴影）或细线图表；硬件用等距细线稿（服务器、显卡），不用写实渲染。
- **毛玻璃 / 虚化**：说明性大字出现时，背后的界面整体虚化变淡，字落在虚化层上（FocusText + 背景模糊）。

## 3. 配色逻辑

- **中性为主**：纸白、卡片白、三级灰（`text` #1B1A18 标题、`textMid` #938D88 副句与注释、`textFaint` #CBC7C4 占位与分隔）。九成画面只有这几种。
- **一个状态色族，各司其职，不混用**：
  - 荧光笔黄 `highlight`（#E1C12B）：只用于「这就是关键那句 / 那个词」，像真的荧光笔划过纸面，一部片最多两三次。
  - 命中橙 `hit`（#DF8318，底 `hitSoft` #FBF0E0）：系统识别出的问题、需要人看的那一项。
  - 通过绿 `ok`（#34796F，底 `okSoft` #E5F1EF）：已核验、已放行、已送达。
  - 警示红只在真正的风险上出现（红旗、超时），且出现即解决。
- **暗场里只有金色的光**，没有别的色相；回到纸面时金色不跟过来。
- 品牌色（如果有）只进 logo 和片尾，或替换「通过绿」。

## 4. 字体与字幕

- **标题**：中文粗黑（PingFang SC / 思源黑体 Semibold–Bold），48–64px，一句话、带句号；上面一行小号等宽编号 `— 03 · 读懂`（mono 14–16px，灰）；下面一行灰色副句 18–22px。标题左对齐，放在画面左上三分之一。
- **引语**：用户原话、关键问题用宋体或衬线（Noto Serif SC / Songti），比标题大，加中文引号，作为一屏的主体（「"体重不涨怎么办"」）。
- **数字**：大数字 72–120px，常规或细字重，等宽数字；旁边一行小标签说明单位和口径。
- **界面字**：14–16px 系统黑体；标签、单号、规则号用等宽。
- **字幕**：没有口播时不用字幕；必须讲的话写成画面里的大字（逐字聚焦出现），不是底部字幕条。有口播时字幕用 Subtitles 组件、浅底深字、小号、底部居中。
- 屏幕上的字都要停够读完的时间（`vw readcheck`：中文 字数 ÷ 4.5 + 1.5 秒）。

## 5. 动效手感

- **镜头慢、界面快**：镜头只做缓推、慢漂、平移；界面里的事情（打字、流式出字、卡片落定、勾选、计数）快而清楚，落点卡在拍上。
- **界面的动作都是真动作**：输入框打字（带光标）、AI 回复流式出现、进度条走到 91%、卡片一张张落进列表、状态胶囊从「识别中」翻到「已识别」。不做与功能无关的装饰动画。
- **出现方式**：字逐字从模糊聚焦（FocusText，0.4–0.6s）；卡片上移 8–16px + 淡入（0.3s，带极小回弹）；数字从 0 滚到终值（0.6–1.2s）。消失多用整体虚化淡出，让下一屏的字落在虚化层上。
- **节奏**：一屏一个读点，读完才动下一个；关键结论停 2–3 秒。全片平均每 2–3 秒一个变化，但每一屏都有停下来读的时间。
- **暗场插叙的动作更慢、更有重量**：光点沿线走、聚光灯缓移、标签纸轻摆；进出暗场用亮度过渡（纸面变暗 / 暗场亮起），不用硬切。

## 6. 镜头语法

一套词汇，不是固定路线。开场和结尾由内容决定。

| 镜头 | 表达 | 适合 |
|---|---|---|
| 纸面微距 + 浅景深，荧光笔划过 | 一个具体的人、一件具体的事 | 开场；痛点的原文 |
| 界面全景缓推，再推进到一个元素 | 系统在工作，细节经得起看 | 演示一次完整流程；一个关键字段 |
| 界面上方叠一句大字，背景虚化 | 这一屏的结论 | 每段的转折句 |
| 单据挂成一排，横移 | 规模、真实的材料 | 「55 张真实理赔单」这种数量 |
| 同一份数据，两个出口并排 | 一次输入，多端产出 | 后台 + 手机；客户端 + 坐席 |
| 暗场：等距线框亮起 / 聚光灯 / 光点时间线 | 系统内部、能力、时间 | 章节插叙；架构一览；耗时 |
| 白色实物条形 / 等距线稿硬件 | 数据和算力被看见 | 指标、样本量、训练资源 |
| 数字墙（一排大数字 + 细线图示） | 工程量、可信度 | 结尾前的「底座」一段 |
| logo 落版，暖白底 + 一句话 | 收束 | 结尾 |

## 7. 声音调色板

- **没有口播**：音乐和音效承担节奏。配乐安静、温和、偏室内乐（钢琴、竖琴、拨弦、轻弦乐铺底，节拍感不强，100–112 BPM）：本工程用 `vw music match --local --sampled=chamber --bpm=100-112`，力度朝高潮走。
- **暗场插叙换一层音色**：低频长音、玻璃或钟琴的单音、一次重拍（`climax2` 指向最重的那次暗场，作曲前面静默半小节）。
- **界面拟音**：键盘（轻）、发送、卡片落定（软咔）、勾选（清脆高音）、计数（细颗粒）、页面推进（极轻的气声）。全部轻，不抢音乐；成组出现时音高按调走（`beats` 的调内序列）。
- **静默**：开场第一句、暗场插叙前、结尾数字墙前各一次短静默。
- **混音**：−14 LUFS；参考片实测低频偏厚（比中频高 1.9 dB）、整体偏安静（−23.8 LUFS），本风格按 −3 dB 低频、−14 LUFS 做。

## 8. 原生手法（标志性的那一下）

按内容挑，用一两个就够。

- **纸到界面**：微距下的一行原文被荧光笔划过，那个词飞出纸面，落成界面里的一个字段。*适合*：病历里的缩写变成待解释项；合同条款变成风险项；发票金额变成对账字段。
- **一句话，走完整流程**：输入框里一句话，系统流式地做完一整套步骤（识别 → 判断 → 生成），每一步一张卡落定，进度走到头。*适合*：一个工单被自动处理；一个查询被拆解；一次审批走完。
- **原文永远在旁边**：每个结论都连一根细线回到原文的那一行，原文高亮。*适合*：可追溯的判断；审计；合规。
- **挂起来的证据**：真实单据一张张挂在一根线上，横移，数字计数到总量。*适合*：样本量；材料清单；历史记录。
- **暗场一亮**：纸面暗下去，暗场里一个金色线框亮起，标出几个能力的位置，再亮回纸面。*适合*：架构总览；能力包；系统边界。
- **同一份画像，两个出口**：后台一张卡和手机上的一条消息同时更新，一根线连着。*适合*：坐席与客户；后台与小程序；内部与外部。
- **数字墙**：一排大数字从上到下落定，每个旁边一条细线图示（色块条、状态点、刻度），最后一行收束成一句话。*适合*：工程量；可靠性；上线成绩。

## 9. 媒介的坑

- 界面画得「像截图」就输了：字号、间距、对齐要比真产品更干净；mock 数据要像真的（单号、时间、金额、状态齐全），但不能是真实敏感数据——涉及人名、证件号一律打码或用假名。
- 卡片阴影一深就变成廉价 PPT：阴影不透明度不超过 8%，不要同时用描边 + 重阴影。
- 状态色撒多了就没有重点：一屏里橙、绿、黄最多出现两种。
- 暗场插叙太长会变成另一部片：每次不超过 8 秒，全片不超过 20%。
- 大字和界面挤在一起：大字出现时背景要虚化变淡，不要直接压在清晰的界面上（`vw readcheck` 会查压字）。
- 字太多：一屏一个读点；读字检查不过就删字或拉长，不要缩小字号。
- 微距景深在 DOM 上不好做：用 three 的 `FilmPost` 景深（对焦到那一行），或用模糊的前后景纸层模拟。

## 10. 引擎（本工程怎么做）

- 纸面与界面：`components/ui`（`AppShell` 应用外壳、`ChatStream` 流式对话、`Cursor` 光标、`GlassCard` 卡片、`ChapterTag` 章节编号、`Editorial` 标题版式、`SnipImage`、`ButtonPortal`）；`shot/FocusText` `FocusSwap`（逐字聚焦、换字）、`MorphLayer`（卡片挪位）、`Light`（`PaperLight` 纸面光 + 颗粒、`LightSweep` 光扫）。
- 设备：`PhoneShot`（2D 手机）、`three/Phone3D`（3D 手机）。
- 暗场插叙：`three/FilmCanvas` + `FilmPost`（景深按世界点对焦、辉光、颗粒、暗角）；需要更写实时走 Blender（`vw blender`）。
- 数据：`anim.countUp`、`flow.tide`；3D 白色条形用 three；细线图示用 SVG。
- 声音：`events` → `autoSpots`（界面拟音按事件自动配）、`beats`（成组落定踩拍）、`vw music match --local --sampled=chamber`（配乐）、`cue.climax2`（暗场重拍前的静默）。
- 检查：`vw readcheck`（读字时间、字幕压字）、`vw review`。
- 样片：`src/films/product-story-test/`（29.5 秒，虚构的售后工单助手）——纸面微距（`world/Macro.tsx`）、纸到界面 + 一句话走完流程（`world/Ui.tsx`）、暗场一亮（`world/Stage.tsx`，FilmCanvas + FilmPost）、数字墙（`world/Numbers.tsx`）。用它做片时先看这里的手法，再按内容重新设计，不照搬故事、镜头和时间轴。
- 第一部正式用它的片子做完后，把能复用的段落（纸到界面、数字墙、暗场线框）收成组件。

## 11. 变化空间（每部片可以自由变的）

故事、主人公、行业、章节数、长度（30 秒到 5 分钟）、界面的具体样子（按项目的真实产品）、暗场插叙的形象（线框 / 聚光 / 光点 / 实物）、配乐的乐器（在室内乐范围内）、品牌色（替换通过绿或只进片尾）、画幅（竖屏时标题移到上方、界面占满宽度）。
